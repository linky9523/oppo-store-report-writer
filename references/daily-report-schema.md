# 日报字段结构与写作规范

日报为纯文本格式（微信/群发风格），单日一份，按固定区块组织。以下为字段结构、写作规范与风格要求。

## 一、固定区块结构

日报按以下顺序组织，每个【】标签独占区块标题行：

```
【日期】YYYY.M.D
【门店】{门店全称}
【姓名】{姓名}

【门店今日数据】
{门店整体数据：客流、整体销量、客流来源等}

【个人今日数据】
{本人各项数据并列一行，不分产品销售/运营服务小类，如"手机独销3台（X9spro、Reno16白&黑）、新增企微3、免费贴膜2张、大众点评1条"}

【典型案例】
{自然段落叙述，不分1）2）3）编号；按"用户画像与诉求→接待与推荐话术→价格沟通与成交"顺序流畅写出，参考范例二/三的连贯行文风格}

【收获与思考】
1、{观察}——{洞察/反思，篇幅参照范例，展开充分}
2、{观察}——{洞察/反思}
3、{观察}——{洞察/反思}

【今日目标达成与积分】
{只写今日销售台数，如"手机独销3台"，不写积分分值}

【明日目标】
1、{目标，不带"销售目标/运营目标"等分类前缀，简洁陈述}
2、{目标}
3、{目标}
```

## 二、各字段写作要点

### 【门店今日数据】
描述门店整体表现，2-4 句。包含：今日售出手机台数、IOT/配件、客流情况（自然到店/低位/被友商虹吸等）。例："门店今日售出5台手机，自然到店客流。"

### 【个人今日数据】
本人各项数据并列写在一行，不要拆成"产品销售""运营服务"两个小类。包含独销台数与机型、贴膜、企微、社媒等。例："手机独销3台（X9spro、Reno16白&黑）、新增企微3、免费贴膜2张、大众点评1条"。无销售则如实写"手机0"。

### 【典型案例】
选当日最有代表性的一单。用自然段落连贯叙述，**不要分 1）2）3）编号**（编号式排版显AI腔）。按"用户画像与诉求 → 接待与推荐话术 → 价格沟通与成交"顺序流畅写出，关键话术与转化点融入行文。未成交案例也可写，重在反思。参考范例二（李周洋）、范例三（杨子江）的连贯行文风格，而非范例一的分号式。

### 【收获与思考】
2-3 条，编号（1、2、3、），每条结构为"观察——洞察/反思"，篇幅要充分展开（参照范例字数，每条 80-150 字），不要过于简短。要求：
- 有具体场景支撑，不空泛。
- 提炼到方法论（如"消费决策受性格与消费心态影响，不能单看消费能力""TA是辅助定位而非限制销售""关注竞品动作借势引流"）。
- 可含自我改进方向。

### 【今日目标达成与积分】
填当日积分（如"积分4分"）。无积分制则写目标达成情况。

### 【明日目标】
1-3 条，分"销售目标"与"运营/导流目标"，要具体可量化（"争取独销1-2台""有效企微>5""小红书抖音>2""为新品预热"）。

## 三、写作风格要求

1. **第一人称**：全文"我"叙述。
2. **简洁务实**：避免客套与AI腔，用导购日常用语。
3. **数字与机型准确**：机型保留品牌规范写法（X9s Pro、Reno16、Find N6、A7 Promax、A6K）。
4. **段落分明**：区块间空行；长文本（售机过程、收获思考）用换行分隔。
5. 可读性：收获思考分条编号清晰；典型案例与售机过程用自然段，不堆文字墙、不用 1）2）3） 分号式编号。
6. **真实性**：数据、机型、话术须基于当日实际，不可编造。

## 四、写日报所需信息清单

写一份完整日报需要以下信息。当用户素材不全时，按本清单逐项核对、缺失优先询问，不可臆测数据与机型。固定字段（门店、姓名、派驻地）可记忆复用，不重复问。

| 序号 | 所需信息 | 说明 | 是否必需 |
|---|---|---|---|
| 1 | 日期 | 默认今天，格式 YYYY.M.D | 必需（默认今天） |
| 2 | 门店 | 门店全称（可固定记忆） | 可记忆 |
| 3 | 姓名 | 导购姓名（可固定记忆） | 可记忆 |
| 4 | 门店今日数据 | 门店今日售出手机台数、客流情况（自然到店/低位/被友商虹吸等） | 必需（客流可缺省） |
| 5 | 个人今日数据 | 独销机型与台数、新增企微、免费贴膜、大众点评、地图好评、付费膜、当换回收、抖音、小红书（按实际有的给） | 必需 |
| 6 | 典型案例 | 用户画像与诉求 + 接待推荐话术 + 价格沟通与成交；无成交则写一个有价值的接待/观察 | 必需 |
| 7 | 收获与思考 | 从当日经历提炼 2-3 条要点（可给要点由 AI 扩写） | 必需（可由AI据案例提炼） |
| 8 | 今日销售台数 | 用于"今日目标达成"区块 | 必需 |
| 9 | 明日目标 | 可由 AI 在今日基础上小幅建议，用户确认 | 可AI建议 |

向用户索取信息时，优先一次性列清单询问，避免反复追问。

## 五、日报存档约定（用于周报自动汇总）

每份日报生成后，**自动存档**到本周日报目录，供周报自动聚合使用：

- 存档目录：`~/.workbuddy/skills/oppo-store-report-writer/data/daily/{年份}/W{ISO周数}/`
- 文件名：`{MM-DD}.md`（如 `09-11.md`）
- 周一~周六每日一份；周日不写日报，其数据在写周报时由用户补充。

每份日报正文末尾**必须**追加一行 metrics 块（不影响人读，供 `scripts/aggregate_weekly.py` 解析），键名固定、无则填 0：

```
<!--metrics phone=1 iot=0 paid_film=0 trade_in=0 ent_wechat=5 dianping=1 map_review=0 free_film=2 douyin=0 xiaohongshu=0-->
```

键名对照（顺序与周报 10 项指标一致）：phone=手机销量(独销)、iot=IOT销量(独销)、paid_film=付费膜销量、trade_in=当换回收数量、ent_wechat=有效授权企微数量、dianping=大众点评数量、map_review=地图好评数量、free_film=免费贴膜数量、douyin=发布抖音数量、xiaohongshu=发布小红书数量。

缺失信息优先询问用户，不可臆测数据与机型。
